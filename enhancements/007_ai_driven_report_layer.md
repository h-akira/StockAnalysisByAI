# ENH-007: レポート生成層の AI 裁量化（固定スクリプトは元データ取得まで・以降は AI ＋ CWD/scripts）

## ステータス

未着手

## 起票日

2026-05-31

## 種別

仕様追加

## 概要

固定スクリプト（`pipeline.py`）の責務を「**EDINET/yfinance からの元データ取得＋一次指標計算＋一次 JSON 出力**」までに留め、それ以降の「雛形外の指標/分析・固定化しづらい例外加工・最終レポートの仕上げ（投資所見）・成果物の妥当性評価」を **AI 裁量**に移す。AI は必要に応じてユーザー CWD の `./scripts/` に**再現可能な加工スクリプト**を新規作成し、一次 JSON を読んで**代替 JSON**を生成、レポートに反映する。一次 JSON は不可侵とし、AI 補正は別ファイルに出す。`./scripts/` には README で記録を残す規律を課す。

> **責務の住み分け（重要）**: 「EPS と対称な一般的補正」のような**全銘柄に共通する決定的処理は固定スクリプト側に
> 入れる**（例: 株式分割補正は EPS が [split_adjust.py](../skills/japan-stock-analysis/scripts/split_adjust.py)、
> PBR が [ENH-008](008_pbr_split_adjustment.md) として固定側で対処する）。AI 裁量に回すのは、固定ロジックでは
> 一般化しづらい**例外**（業種・銘柄に固有で網羅が困難な加工）と、雛形外の分析・所見・最終品質チェック。
> **PBR 分割補正は固定側（ENH-008）が本線であり、本 enhancement の対象例ではない。**

> **本 enhancement は設計の根幹（責務分界）に関わる。** [init_plan.md](../init_plan.md) は初期計画の
> 記録であり**不可侵**（書き換えない）。本 enhancement が示す責務分界は、init_plan.md を上書きする現行設計の
> 正である **[architecture.md](../architecture.md) に集約**する（別途の改訂ノートは作らない。AGENTS.md でも
> architecture.md を現行の正と定義済み）。init_plan.md 本体には手を入れない。本起票は設計提案であり、
> 実装着手は別途レビューの後とする。

## 背景・動機

manual_test_03（NTT 9432・[review_report.md](../manual_test_03/review_report.md)）で 2 つの構造的弱点が顕在化した:

1. **固定ロジックでは網羅しきれない加工要件・分析要求が常に出てくる**: NTT の PBR 分割未補正
   （7 期中 5 期で 0.02〜0.07 倍の異常値）は、EPS と対称な一般補正なので**固定側で直せる**
   （[ENH-008](008_pbr_split_adjustment.md)）。だが、このように一般化できる補正を固定で潰しても、
   業種・銘柄に固有でパターン化しづらい例外や、ユーザーが求める雛形外の指標・可視化は際限なく出てくる。
   それらを固定スクリプトで網羅し続けるのは非現実的で、未対応の間は誤値や不足が成果物に残る。
   **「一般化できる補正は固定、できない例外・要望は AI」という受け皿が要る。**
2. **AI が成果物を仕上げる余地が無い**: [report_template.html.j2](../skills/japan-stock-analysis/templates/report_template.html.j2)
   は「警告＋グラフ＋参照」固定で、投資所見や雛形外の指標を載せる場所が無い。AI 介在型 Skill なのに、
   定性判断・例外対応・最終品質チェックを AI が担えない。

本プロジェクトの設計思想は「会社差・定性判断は AI に委ねる」（[AGENTS.md](../AGENTS.md) §設計思想）。
レポート生成層までこの思想を一貫させ、**固定スクリプトは監査可能な一次計算に徹し、例外対応と仕上げを
AI に委ねる**ハイブリッドにする。ただし AI 生成スクリプトの「使い捨て」による再現性喪失を避けるため、
`./scripts/` への永続化と README 記録を規律として課す。

## 要件

### R1. 責務分界（ハイブリッド）

- **固定スクリプト（`pipeline.py` 系）が担う範囲**: XBRL 取得・要素抽出・timeseries・split_adjust・
  一次指標計算（PER/PBR/ROE 等、現行どおり）・一次 JSON（`data_{code}.json`）出力・warnings。
  ここは引き続き pytest で回帰を担保する**監査済みの土台**。一次計算はベストエフォートで出し続ける
  （不確かな期も値＋warning を出す）。**EPS/PBR の分割補正のような全銘柄共通の一般処理もここに含める**
  （split_adjust / [ENH-008](008_pbr_split_adjustment.md)）。
- **AI が担う範囲**: 一次 JSON を読んでの妥当性評価／固定で一般化しづらい例外加工／雛形外の指標・
  分析（ユーザー要望）／最終レポートの仕上げ（投資所見含む）／不自然な値が残らないことの確認。

### R2. 一次情報の不可侵と代替 JSON（元データと計算値の明示分離）

- `data_{code}.json`（固定スクリプト生成）は**一次情報として上書き・改変しない**。常に追跡可能に保つ。
- **一次 JSON 内で「元データ」と「計算値」を明示的に区別する**（境界を明確にし、AI がどこを上書きして
  よいかを一意にする）:
  - **元データ（不可侵）**: XBRL から抽出した生の財務数値（現 `financials` の NetSales / OperatingIncome /
    ProfitLoss / EarningsPerShare / TotalAssets / NetAssets / InterestBearingDebt / 各 CF / SharesOutstanding）と、
    yfinance の生株価（現 `metrics.StockPrice`）。これは AI も補正スクリプトも**書き換えてはならない一次値**。
  - **計算値（AI 上書き可）**: 財務値・株価から導出する指標（現 `metrics` の OperatingMargin / NetMargin /
    ROE / EquityRatio / DERatio / SalesGrowth / ProfitGrowth / BPS / EPSForPER / PER / PBR）と、派生量
    （現 `financials.FreeCF` は OperatingCF+InvestingCF の計算値なので「計算値」側に位置づけ直す）。
    これらは固定スクリプトがベストエフォートで出すが、AI が代替 JSON で**再計算・上書きしてよい**。
  - スキーマ上はブロックを分けるか、各値に `source: "xbrl" | "yfinance" | "computed"` 等のタグを付けて
    区別する（詳細は未確定事項で詰める）。`docs/json_schema.md` に反映。
- AI による補正・追加分析は、`.japan-stock/scripts/` のスクリプトが**元データを入力に計算値を再計算**し、
  **代替 JSON** を**全量**生成する（差分のみではなく、レポートが単独で読める完全な JSON）。
  **元データ部分は一次 JSON からそのまま引き継ぎ、計算値部分のみ差し替える**。
- **代替 JSON は単一に集約する（#5 確定・チェーン方式）**: ファイルは `data_{code}_adjusted.json` の 1 つ。
  複数の補正・追加分析が生じても、後続スクリプトは**既存の代替 JSON（無ければ一次 JSON）を入力に積み重ね**、
  同じ 1 ファイルを更新する。複数ファイルは作らない。補正の履歴・各段の根拠はメタ情報に記録する。
- レポート生成は「**代替 JSON があればそれ、無ければ一次 JSON**」を読む（優先規則はこれだけ。複数代替の
  マージ判断は不要＝単一集約のため）。代替には「どの計算値をどう補正したか」「典拠（XBRL 要素/コンテキスト/
  有報）」「一次計算値との対比」をメタ情報として持たせる。
- 雛形外の独自指標（ユーザー要望）も「元データ＋（必要なら他の計算値）から導く計算値」として同じ代替 JSON に
  追加できる。元データは常に不可侵。

### R3. CWD レイアウトと `.japan-stock/` 作業領域の規約

- 配置の基点は **ユーザーが Skill を起動した CWD**（`.claude/skills/...` ではなく、成果物が出るディレクトリ。
  例: `manual_test_03/`）。CWD 内は「**見せる成果物は直下、作業物は隠しディレクトリ**」で分ける（#4 確定）:
  - **CWD 直下（成果物）**: `report_{code}.html` / `data_{code}.json`（一次）/ `data_{code}_adjusted.json`（代替）。
  - **`.japan-stock/`（作業物・隠しディレクトリ）**: AI 生成スクリプト群と銘柄固有キャッシュ。
    - `.japan-stock/scripts/`: `{code}_report.py`（参考実装のコピー）、`{code}_*.py`（補正・独自指標）、`README.md`。
    - `.japan-stock/cache/`: 銘柄固有キャッシュ（`xbrl/` `derived/` `mappings/` `split_adjust/` `prices/`。[ENH-009](009_cache_relocation_cwd.md)）。
  - **gitignore**: `.japan-stock/` を無視対象に推奨（ユーザーのリポジトリを汚さない。成果物は直下に残る）。
- **ファイル名は銘柄番号で識別、日付は付けない**（例: `9432_pbr_*.py` は固定側 ENH-008 なので実際は
  `9432_segment_analysis.py` のような雛形外分析が中心）。同一 CWD で複数銘柄を扱うため銘柄番号は必須。
- `.japan-stock/scripts/README.md` を必須とし、各スクリプトについて「対象銘柄／目的／入力（読む JSON）／
  出力（生成する代替 JSON 等）／一次計算値からの変更内容と根拠」を記録する。再現性・監査性を担保する規律。
- スクリプトは一次 JSON（または既存の代替 JSON。#5 チェーン）を入力に、**決定論的**に代替 JSON を生成する
  純粋な処理にする（乱数・時刻依存を避け、再実行で同じ結果）。**書き込み先は CWD 配下のみ**（`.japan-stock/`
  と成果物）。Skill 配下・グローバルキャッシュ・CWD 外には書かない。元データ（XBRL/株価生値）は変えない（#7）。

### R4. SKILL.md フロー追加（評価と仕上げの反復ループ）

- 既存 §7（出力の解釈）の後に、新ステップ「**レポートの評価と仕上げ**」を追加する。**所見や補正は HTML の
  後付けではなく、レポート生成スクリプト（CWD/scripts のコピー）に書き込まれ、その実行結果として HTML に
  織り込まれる**。標準ケースは初回出力のまま追記なしで完成し、補正・所見が要る場合だけ「編集 → 再実行」の
  ループを回す（＝「一度 HTML を出してから、必要ならスクリプトを編集して再生成する」反復方式）。
  1. success 後、`assets/` の参考実装を CWD/scripts にコピーして実行し、**まず標準レポート（HTML）を一度
     出力する**。
  2. **出力された HTML と一次 JSON を AI が読んで評価する**: 不自然な値（PBR が極端に小さい/大きい、指標が
     桁外れ、分割をまたぐ系列の不連続等）が無いか、所見を加えるべきか。
  3. 問題が無ければそのまま完成。**補正・所見・雛形外の指標が必要なら、CWD/scripts のコピーを編集**
     （所見セクションの記述、補正計算による代替 JSON 生成、独自指標の追加）し、**再実行して仕上げる**。
     必要に応じてこの評価→編集→再実行を繰り返す。
  4. 編集した場合は `./scripts/README.md` に記録を残す。
  5. **投資所見**（財務トレンド・バリュエーション・リスク）は、完成した HTML を踏まえて一定の自由度で
     記述し、スクリプト経由でレポートに織り込む（断定的な売買推奨は避ける）。
- **終了条件と上限（#2 確定・SKILL.md ガイドで運用）**: 「明白な異常（指標が負・ゼロ・桁外れ、分割をまたぐ
  系列の不連続等）が残らず、所見も書けた」と AI が判断したら終了する。完璧を目指して延々ループしない。
  **2〜3 回直しても収束しなければ、直しきれない旨と残る懸念をユーザーに明示して止める**（コードで回数を
  強制はしない。SKILL.md のガイドラインとして示す）。
- **数値の透明化（#1 確定・見張りコードは作らない）**: AI が計算値を補正・追加した場合は、**一次計算値と
  補正後の値の対比をレポート/応答でユーザーに提示**し、何をどの根拠で変えたかを明示する。元データ一致を
  機械検証する専用チェッカーは設けず、透明化と人間レビューで担保する。
- これらは [AGENTS.md](../AGENTS.md) §設計思想（会社差・定性判断は AI に委ねる、コード固定化に走らない）と
  一貫させる。

### R5. ガードレール（数値の正確性・投資助言の節度）

- AI 生成スクリプトの計算は、可能な限り**典拠（XBRL の実値・有報の遡及列）に基づく**こと。推測値・
  暗算値を代替 JSON に書かない（[ENH-004](004_mapping_rationale_value_cross_check.md) の rationale 規律と同じ精神）。
- 補正の前後で一次値と代替値を対比してユーザーに提示し、何をどう変えたか透明化する。
- **専用の数値検証 CLI（元データ一致チェッカー等）は作らない**（#1 確定）。PBR のような一般補正は固定側
  （[ENH-008](008_pbr_split_adjustment.md)）に寄せたため AI が計算値をいじる頻度は低く、重い機械検証より
  上記の透明化＋人間レビューで担保する方が本システムの思想（AI 裁量＋人間確認）に合う。
- 投資所見は**断定的な売買推奨を避け**、事実（数値）と解釈（所見）を区別する。
- レポートテンプレートは「データ品質 warning」「AI 所見」「補正の記録」を**別セクション**にし混ぜない。

### R6. テンプレート拡張

- `report_template.html.j2` に「分析コメント（AI 所見）」セクションと、補正があった場合の「補正の記録」
  セクション（一次値→補正値の対比・根拠・生成スクリプト名）を追加する。render 時に AI が用意した
  内容（Markdown/HTML）を流し込む（例 `{{ analyst_comment | safe }}` / `{{ adjustment_notes | safe }}`）。

### R7. 最終レポートの出力方式（参考実装の CWD コピー方式）

レポート生成は「**参考実装（assets）を CWD にコピーして使う**」方式で扱う（AI が毎回 HTML を手書き
しない／直接実行の固定スクリプトにも完全固定しない、中間）:

- **参考実装の配置を `scripts/` → `assets/` に降格**: html 生成（現 `scripts/html_report.py` ＋
  `templates/report_template.html.j2`）は「**直接実行される固定スクリプト**」ではなく「**コピーされて使われる
  参考雛形**」なので、`skills/japan-stock-analysis/assets/`（Claude Agent Skills 慣習の補助ファイル置き場）に
  移す。これにより `scripts/` は「`${CLAUDE_SKILL_DIR}/scripts/X.py` で**直接実行されるパイプライン専用**」と
  役割が明確になり、「実行用」と「コピー元」の二役混在を解消する。参考実装は pytest で回帰を担保する
  無垢な基準実装として維持。
- **初回のみ CWD へコピーして実行（#6 確定）**: 初回 analyze 時に `assets/` の参考実装を
  `.japan-stock/scripts/{code}_report.py` に**コピー**する。標準ケース（補正不要）はそのまま実行し、参考実装と
  同一の標準レポートを得る（再現性◎）。**コピーは初回の一度だけ**で、以降は CWD のコピーをそのまま使う。
  `assets/` 側の参考実装を更新しても**既存 CWD のコピーには伝播させない**（別 CWD で同一銘柄を再分析しない
  前提＝[ENH-009](009_cache_relocation_cwd.md) と整合するため、伝播漏れの実害は出にくい）。
- **例外時はコピーを編集して再実行**: まず標準レポートを一度出力し、その HTML と一次 JSON を評価したうえで、
  固定で一般化しづらい例外加工・雛形外の図表・ユーザー要望の独自分析・AI 所見が必要なときだけ、
  AI が**コピーを編集 → 再実行**して仕上げる（評価→編集→再実行の反復。詳細フローは R4）。編集後スクリプトは
  `./scripts/` に永続し、
  `./scripts/README.md` に「参考実装からの差分・目的・対象銘柄・入出力」を記録する（R3）。`assets/` の
  参考実装は無垢のまま残るので、いつでも基準実装と差分を比較できる。
- これにより AI は「グラフをゼロから書く」手間を負わず参考実装を出発点にでき、会社固有の仕上げを
  再現可能な形で残せる。代替 JSON（R2）を入力に、CWD のコピー（標準ならそのまま／例外なら編集済み）が
  最終 HTML を生成する。

> 配置の含意: `scripts/` = 直接実行されるパイプライン（`pipeline.py` 等、`${CLAUDE_SKILL_DIR}/scripts/X.py`
> 起動）。`assets/` = コピーされて使われる参考雛形（レポート生成実装・テンプレート）。この区別を
> [SKILL.md](../skills/japan-stock-analysis/SKILL.md) §4 と [AGENTS.md](../AGENTS.md) §スクリプト起動方法に反映する。

## 実現案

### 案1: ハイブリッド ＋ ./scripts/ 永続化 ＋ 代替 JSON（採用方針）

上記 R1〜R6。固定スクリプトは監査済みの一次計算まで、AI が評価・例外加工・仕上げを担い、加工は
`./scripts/`（銘柄番号命名・README 必須）に永続化、出力は一次 JSON を不可侵としつつ全量の代替 JSON。
再現性（pytest が効く土台＋永続スクリプト＋README）と AI 裁量（会社固有加工・所見）を両立。

### 案2: 全面移行（固定スクリプトは生データ取得のみ）— 不採用

指標計算・グラフ・レポートを全て AI が使い捨てスクリプトで生成。最も柔軟だが、(a) 監査済み一次計算が
失われ回帰テストが効かない、(b) 金融数値の正確性リスク、(c) 毎回のトークン/時間コスト、が大きい。
本プロジェクトのリスク許容度に合わないため採らない。

### 案3: 現状維持＋個別バグ対応 — 不採用（後退）

投資コメントや雛形外の分析要求を、固定テンプレ・固定指標として個別実装し続ける。例外と要望の網羅は
終わらず、AI 介在型の強みを活かせない。（PBR のような一般補正は固定でよいが、それは本案の論点ではない。）

## 決定事項（レビュー指摘を受けて確定済み）

実装着手前に詰めるべき論点としてレビューが挙げた 7 点は、以下のとおり確定し本文（R2〜R7）に反映済み:

- **#1 数値正確性の sanity-check**: 専用検証 CLI（元データ一致チェッカー）は**作らない**。PBR 等の一般補正を
  固定側（ENH-008）に寄せたため AI が計算値をいじる頻度は低く、**一次値↔補正値の対比の透明化＋人間レビュー**で
  担保する（R5）。
- **#2 反復の終了条件・上限**: SKILL.md ガイドで運用。明白な異常が残らず所見も書けたら終了。**2〜3 回で
  収束しなければ残る懸念を明示して止める**。コードで回数強制はしない（R4）。
- **#3 スキーマ移行 v1.0 → v1.1**: 下記「実装計画」に分解。
- **#4 CWD レイアウト**: 成果物は CWD 直下、作業物（スクリプト・銘柄固有キャッシュ）は `.japan-stock/` 配下。
  gitignore は `.japan-stock/`（R3、[architecture.md](../architecture.md) §6 にレイアウト図）。
- **#5 代替 JSON**: 単一 `data_{code}_adjusted.json` に**チェーン集約**。レポートは「代替＞一次」優先のみ（R2）。
- **#6 原本コピー**: 命名 `{code}_report.py`、**初回のみコピー・原本更新は非伝播**（R7）。
- **#7 実行範囲ガード**: SKILL.md 規約として、書き込みは CWD 配下のみ・元データ不変・決定論的（R3）。

> 「init_plan.md を上書きする現行設計の正」は **[architecture.md](../architecture.md) に集約**する
> （別ファイルの改訂ノートは作らない。AGENTS.md でも architecture.md を現行の正と定義済み）。

## 実装計画（スキーマ移行 v1.0 → v1.1 のサブタスク分解）

本 enhancement は規模が大きいので、以下の段階に割って実装する（順序は依存関係順）:

1. **スキーマ設計（v1.1）**: 一次 JSON で元データ/計算値を区別する表現を決める。候補は (a) ブロック分割
   （`raw` / `computed`）か (b) 各値に `source: "xbrl" | "yfinance" | "computed"` タグ。`docs/json_schema.md` を v1.1 に更新。
2. **`FreeCF` の再分類**: `financials`（元データ）から計算値側へ移す。後方互換（v1.0 を読む既存コードがあれば）
   の確認と `schema_version` の bump。
3. **`json_export.py` 改修とテスト更新**: v1.1 を出力するよう変更し、既存 pytest fixture / テストを更新。
4. **代替 JSON の入出力**: `.japan-stock/scripts/` のスクリプトが一次 JSON（または既存代替）を読み、計算値を
   再計算して全量の代替 JSON を出す仕組み（チェーン・メタ情報）。
5. **`assets/` 化とレポートの代替優先読み込み**: `html_report.py`＋テンプレートを `assets/` に移し、所見・補正記録
   セクションを追加、代替 JSON があればそれを読む（R6/R7）。CWD コピー＆評価→編集→再実行フロー（R4）。
6. **SKILL.md 反映**: §7 後の「評価と仕上げ」ステップ、`scripts/`↔`assets/` の区別（§4）、実行範囲規約（R3/#7）。

> なお [ENH-009](009_cache_relocation_cwd.md)（銘柄固有キャッシュの CWD 移設）と CWD レイアウトを共有するため、
> 実装は ENH-009 と前後関係を調整する（`.japan-stock/cache/` の確定が両者にまたがる）。
