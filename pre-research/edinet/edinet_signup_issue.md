# EDINET API 利用登録での詰まり: 状況整理と対処メモ

記録日: 2026-05-11

## 1. 発生事象

EDINET の **閲覧サイト経由「EDINET APIの利用登録はこちら」** から新規登録を試行。

| # | 試行 | 結果 |
|---|------|------|
| 1 | PC で新規登録、SMS 2段階認証コード入力 | リダイレクト後、白い画面で停止 |
| 2 | PC で再試行（新規登録） | 同上（再現性あり） |
| 3 | スマホでサインアップ試行 | メアドが「既に登録済み」となり進めない |
| 4 | スマホでサインイン（既存アカウント、パスワード入力） | 2段階認証SMSが送られ、認証通過 |
| 5 | スマホで2段階認証完了直後 | 同じく白い画面、「ポップアップがブロックされました」表示あり |

→ 1回目の試行でアカウント自体は生成済み。サインインで2段階認証まで通ることは確認できた（**「メアド登録済み」は解決済み問題**）。残る課題はSMS認証直後の白画面で、原因は**ポップアップブロックの可能性が極めて高い**。

## 1.5 追加の試行（スマホ）

スマホでもSMS 2段階認証は通ったが、**認証完了後にPCと同じく画面が白くなった**。
ただし、スマホでの試行中に**「ポップアップがブロックされました」という旨の通知**が出ていた。

→ これが直接の原因と思われる。EDINETの認証フローは Azure AD B2C を介して**複数ドメイン間でリダイレクト＋ポップアップ**を行う設計のため、ポップアップブロックが有効だと最終ステップで白画面のまま停止する。
→ PC側でも同様にポップアップが（無音で）ブロックされた可能性が高い。

## 1.6 解決 ✅

PC の Chrome で **設定 → プライバシーとセキュリティ → サイトの設定 → ポップアップとリダイレクト** を「許可」に変更したところ、SMS 2段階認証完了後に正常に画面遷移し、APIキーの発行まで完了した。

**根本原因**: Chrome のポップアップブロック（デフォルト有効）が、Azure AD B2C 経由の認証後リダイレクトをブロックしていた。

**解決手順まとめ**:
1. Chrome アドレスバー右のポップアップブロックアイコン、または設定から `disclosure2.edinet-fsa.go.jp` のポップアップ・リダイレクトを許可
2. サインイン画面（新規登録ではない）からメアド＋パスワードで入り直す
3. SMS 2段階認証を通過 → APIキー発行画面へ遷移する

## 2. わかっていること

### 2-0. これは「珍しい事象」ではない — 評判についての所感

複数の状況証拠から、EDINET の登録/認証フローは**広く評判が悪い**と言ってよい。

- **公式FAQ Q8 として明示掲載されている**（[ログイン（多要素認証含む）FAQ](https://disclosure2dl.edinet-fsa.go.jp/guide/static/submit/WZEK0090_001.html)）
  - 公式が「よくある質問」に載せる時点で件数が一定以上ある
  - Q8の他にも Q13/Q14/Q15/Q16 と**多要素認証絡みのトラブルだけで5項目**
- **日経新聞でも不満が報じられた**: [新「EDINET」に不満噴出 金融庁、改善作業を継続 (日経, 2023)](https://www.nikkei.com/article/DGXZQOFL00022_W3A100C2000000/)
  - 2023年の大規模システム更改後、検索遅延・エラー多発で「市場で不満が噴出」と報道
  - 金融庁が「原因究明とシステム改善を継続」と表明する事態
- **複数の技術ブログ・Qiita記事が "ハマりポイント" として登録フローを取り上げている**
  - 電話番号入力フォーマットの罠（`080-XXXX-XXXX` → `80-XXXX-XXXX` で `+81` 選択）
  - ポップアップブロックで遷移失敗
  - ヘルプデスクに多要素認証クリア依頼を投げる事例
- **構造的な要因**: 認証基盤に Microsoft Azure AD B2C を採用し、複数ドメインをまたぐリダイレクト構成のため、わずかな環境差で破綻しやすい

**結論**: 今回の事象はあなただけの問題ではなく、登録フローの設計に起因する既知の体感不良。**自力での突破にこだわらず、早めにヘルプデスクへ連絡するのが最短**。

### 2-1. 「白い画面」は公式に既知の事例

EDINET公式 FAQ「[ログイン（多要素認証含む）](https://disclosure2dl.edinet-fsa.go.jp/guide/static/submit/WZEK0090_001.html)」に該当Qあり。

> **Q8. EDINETの多要素認証画面での認証後、画面が白くなる事象が発生しました。どうすればよろしいでしょうか。** (2023-01-04)

公式の推奨対処:

- 以下ドメインへの通信がフィルタリング/プロキシ/拡張機能でブロックされていないか確認
  - `https://ajax.aspnetcdn.com/`
  - `https://fsaedinetauth.b2clogin.com/` ← Microsoft Azure AD B2C認証ドメイン
  - `https://disclosure2dl.edinet-fsa.go.jp/`
  - `https://disclosure2.edinet-fsa.go.jp/`
  - `https://submit2.edinet-fsa.go.jp/`
  - `https://repository.secomtrust.net/`
- 「書類提出用端末要件」に沿った端末設定（推奨ブラウザ、信頼済みサイト登録、Cookie/JavaScript有効化）

### 2-2. メアド「既に登録済み」状態の意味 ✅ 解決済み

1回目のPC試行でアカウント自体は生成されていた。サインアップ画面で「登録済み」と出るのはそのため。**サインイン画面からパスワード入力で問題なく入れる**ことを確認済み。残課題はAPIキー発行画面に到達できていないことのみ。

### 2-3. アカウント/APIキーの削除は可能

仕様書によれば、APIキー削除のうえで再度アカウント作成からやり直すフローが用意されている。サインイン自体は可能とわかったので、必要があれば自力でも操作できる見込み。

### 2-4. 「平日 9:00〜17:15」の時間制限は今回の事象とは無関係

確認したところ、EDINETの時間制限は次のとおり棲み分けされている。

| 機能 | サービス時間 |
|------|------------|
| **提出サイト**（書類を提出する企業向け） | **平日 9:00〜17:15** |
| **閲覧サイト**（一般利用・書類検索） | **24時間/365日** ※定期保守時を除く |
| **API利用登録・APIキー発行**（閲覧サイト経由） | **24時間/365日** |
| **API呼び出し** | **24時間/365日** |

「9:00〜17:15」は提出者（=書類を出す企業）向けの提出サイトの受付時間で、今回触っている「閲覧サイト経由のAPI利用登録」とは別系統。公式の[稼働状況ページ](https://www.fsa.go.jp/search/edinet-Information/information-01.html)でも現在は計画停止予定なし。
→ **時間帯を待っても白画面は解消しない**。原因は依然としてポップアップブロックの可能性が最も高い。

## 3. 推奨アクション（優先順）

> **方針更新**: スマホでの試行中に「ポップアップがブロックされた」表示が出ていたことが判明。これが直接の原因の可能性が極めて高い。**まず Step 1（ポップアップ許可）を試す。** PC側でも同様にポップアップが無音でブロックされていた可能性あり。

### Step 1: ポップアップブロックを解除してから再試行 ← **最優先**

**スマホ (iOS Safari)**:
1. 設定 → Safari → **「ポップアップブロック」をOFF**
2. 設定 → Safari → **「サイト越えトラッキングを防ぐ」を一時OFF**
3. Safariを完全終了して再起動
4. EDINETの**ログイン画面**から既存アカウントに入る（新規登録ではない）

**スマホ (Android Chrome)**:
1. Chrome右上「︙」→ 設定 → サイトの設定 → **ポップアップとリダイレクト → 許可**
2. または `disclosure2.edinet-fsa.go.jp` を個別に許可

**PC**:
- ブラウザ右上のアドレスバー付近に**ポップアップブロックアイコン**が出ていないか確認 → クリックして「このサイトのポップアップを常に許可」
- **シークレットウィンドウ**＋拡張機能を全部無効にしてから再試行
- Cookie/サイトデータをクリアしてからログイン

ポップアップを許可した状態でログイン画面から入れば、SMS認証後にAPIキー発行画面まで進めるはず。

### Step 2: 既存アカウントへのログイン試行 ✅ 一部達成

スマホでサインイン→2段階認証通過まで確認済み。あとは認証直後の白画面（ポップアップブロック起因の可能性大）を Step 1 の対処で解消できるかが残る課題。

### Step 3: EDINETヘルプデスクへ連絡

問い合わせ先:

- **EDINET APIヘルプデスク（運用委託先）**: `edinet-helpdesk@cec-ltd.co.jp`
  - API利用登録・APIキー関連の問い合わせ先として実績あり
- **関東財務局 理財部 理財第2課**: `048-600-1119`
  - 主に提出者向け窓口だがEDINET全般の照会先
- **問い合わせフォーム経由**: [財務省関東財務局 EDINET問い合わせ窓口](https://lfb.mof.go.jp/kantou/disclo/address.htm)

**伝えるべき内容**:
- 事象: 「EDINET API利用登録（閲覧サイト経由）でSMS2段階認証コード入力後に画面が白くなる事象が連続2回発生」
- 試した対処: ブラウザ変更・拡張無効化・別端末（スマホ）でも継続
- 状態: 同メアドが「登録済み」となっており、ログインもAPIキー取得も未完了
- 希望: 該当アカウントの状態確認、または削除のうえ再登録できるようにしてほしい
- 環境情報: OS（macOS Darwin 24.6.0）、使用ブラウザ名/バージョン、発生日時

### Step 4: 緊急回避策（やむを得ない場合のみ）

別メールアドレスで新規登録。ただし古いアカウントが残ったままになるためサポートへの整理依頼は推奨。

## 4. 当面の代替手段（EDINET詰まり中の作業継続）

EDINETが使えない間は、以下で先行して試作を進められる:

- **yfinance**: 登録不要・即使える。プロトタイプの動作確認はこれで十分
- **J-Quants API Free**: 別途登録だがEDINETほどの認証フロー問題は報告されていない

詳細は [research_summary.md](research_summary.md) を参照。
